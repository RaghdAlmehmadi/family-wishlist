# أمنيات العائلة

رحلة شتوية، وهدايا ننتظرها بكل حب.
موقع عربي بسيط تتشارك فيه العائلة قائمة المشتريات، والبيانات محفوظة في Supabase، وأي تعديل يظهر على جميع الأجهزة خلال ثانية تقريبًا.

---

## محتويات المشروع

| الملف | وظيفته |
|---|---|
| `index.html` | هيكل الموقع |
| `css/styles.css` | التصميم (الجوال والآيباد والكمبيوتر) |
| `js/app.js` | الواجهة: الصفحات، التصنيفات، القوائم، النموذج، البحث، الإحصائيات |
| `js/store.js` | الاتصال بقاعدة البيانات والصور والمزامنة اللحظية |
| `js/art.js` | الأيقونات الخطية، والعلمان، ومشهد الهيدر الشتوي مع ماما وروان، والثلج |
| `js/config.example.js` | نموذج ملف الإعداد |
| `supabase/schema.sql` | الجداول والعلاقات والصلاحيات وتخزين الصور والمزامنة (وترقية الإصدار الأول) |
| `supabase/open-access.sql` | اختياري: موقع بلا كلمة سر |
| `scripts/build-config.mjs` | ينشئ `js/config.js` من متغيرات البيئة عند النشر |
| `netlify.toml` و `vercel.json` | إعدادات النشر الجاهزة |

لا يحتاج المشروع إلى أي حزم أو أدوات بناء؛ هو موقع ثابت يتصل مباشرة بـ Supabase.

---

## إن كنتِ أعددتِ الإصدار الأول من قبل

1. شغّلي `supabase/schema.sql` مرة أخرى في **SQL Editor** (آمن لإعادة التشغيل). سيضيف قسم المكياج وتصنيفاته، ويحدّث تصنيفات الصيدلية، وينقل أي منتج كان في تصنيف «المكياج» داخل الصيدلية إلى قسم المكياج (تصنيف «منتجات أخرى»). لا يُحذف أي منتج.
2. ارفعي ملفات الموقع الجديدة مكان القديمة. الإعداد ومتغيرات البيئة وكلمة السر كما هي.
3. اختياري: الأعمدة القديمة (السعر، العملة، المتجر، الرابط، الملاحظات، البلد، الأولوية) لم تعد مستخدمة. لحذفها نهائيًا:
   ```sql
   alter table public.products
     drop column if exists price,  drop column if exists currency, drop column if exists country,
     drop column if exists store,  drop column if exists url,      drop column if exists notes,
     drop column if exists priority, drop column if exists added_by, drop column if exists purchased_by;
   alter table public.sections   drop column if exists emoji;
   alter table public.categories drop column if exists emoji;
   ```

إن كان المشروع جديدًا فتجاهلي هذا القسم وابدئي من «أولًا».

## أولًا: إعداد Supabase خطوة بخطوة

### 1) أنشئي المشروع
1. ادخلي إلى [supabase.com](https://supabase.com) وسجّلي الدخول.
2. **New project** ← اختاري اسمًا (مثل `family-wishlist`) وكلمة سر لقاعدة البيانات واحفظيها، ثم أقرب منطقة لكم.
3. انتظري دقيقتين حتى يجهز المشروع.

### 2) أنشئي الجداول
1. من القائمة الجانبية: **SQL Editor** ← **New query**.
2. انسخي محتوى `supabase/schema.sql` كله والصقيه، ثم اضغطي **Run**. يجب أن تظهر رسالة نجاح.

ما يُنشئه الملف:

| الجدول | المحتوى |
|---|---|
| `members` | أفراد العائلة الثمانية |
| `sections` | الأقسام الستة: الصيدلية، المكياج، العطور، الشنط، الملابس، الإكسسوارات |
| `categories` | 10 تصنيفات للصيدلية و6 للمكياج، وتُضاف غيرها من الموقع في أي قسم |
| `products` | اسم المنتج، ووصفه، وصورته، وحالة الشراء |
| `product_members` | ربط المنتج بصاحبه، أو بعدة أشخاص إن كان مشتركًا |

ويُنشئ أيضًا الدالة `save_product` (تحفظ المنتج وأصحابه في عملية واحدة)، وحاوية الصور `product-images` (حدّها 5 ميغابايت للصورة)، وسياسات الأمان RLS، وتفعيل المزامنة اللحظية. لا يحتوي على أي منتجات تجريبية.

### 3) أنشئي حساب العائلة (كلمة سر واحدة للجميع)
1. **Authentication** ← **Users** ← **Add user** ← **Create new user**.
2. اكتبي بريدًا تملكينه (لا يظهر لأحد) وكلمة سر يسهل على العائلة تذكّرها ويصعب تخمينها.
3. فعّلي **Auto Confirm User** ثم **Create user**.

كلمة السر هذه يكتبها كل فرد مرة واحدة على جهازه، ولا تُكتب في الكود ولا في أي ملف.

### 4) أوقفي التسجيل العام (خطوة مهمة)
**Authentication** ← **Sign In / Providers** ← عطّلي **Allow new users to sign up** ← **Save**.
بدون هذه الخطوة يستطيع من يعرف رابط المشروع أن ينشئ حسابًا لنفسه.

### 5) انسخي الرابط والمفتاح العام
- **رابط المشروع**: في زر **Connect** أعلى لوحة المشروع، بالشكل `https://xxxx.supabase.co`.
- **المفتاح العام**: **Settings** ← **API Keys** ← **Publishable key** (يبدأ بـ `sb_publishable_`). إن ظهر زر **Create new API keys** فاضغطيه أولًا. المفتاح القديم `anon` يعمل أيضًا.

> لا تضعي المفتاح السري (`sb_secret_...`) أو `service_role` في الموقع أبدًا. الموقع وسكربت النشر كلاهما يرفضان المفتاح السري.

### 6) تحقّق سريع (اختياري)
- **Database** ← **Publications** ← `supabase_realtime`: الجداول `products` و `product_members` و `categories` مفعّلة.
- **Storage**: الحاوية `product-images` موجودة.

## ثانيًا: متغيرات البيئة

| المتغير | القيمة | إلزامي؟ |
|---|---|---|
| `SUPABASE_URL` | رابط المشروع | نعم |
| `SUPABASE_PUBLISHABLE_KEY` | المفتاح العام (أو باسم `SUPABASE_ANON_KEY` للمفتاح القديم) | نعم |
| `WISHLIST_FAMILY_EMAIL` | بريد حساب العائلة من الخطوة 3 | نعم في الوضع المحمي |
| `WISHLIST_AUTH_MODE` | `password` (الافتراضي) أو `open` | لا |

المفتاح العام مصمَّم ليظهر في المتصفح؛ الحماية الفعلية من سياسات RLS التي لا تسمح بأي قراءة أو كتابة قبل الدخول بكلمة سر العائلة.

## ثالثًا: التشغيل على جهازك للتجربة

1. انسخي `js/config.example.js` باسم `js/config.js` واملئي القيم.
2. من داخل مجلد المشروع:
   ```bash
   python3 -m http.server 8080
   # أو
   npx serve .
   ```
3. افتحي `http://localhost:8080` (عبر الخادم، لا بالنقر المزدوج على الملف).

## رابعًا: النشر على الإنترنت

### GitHub Pages (مجاني، والنشر تلقائي)
المستودع فيه ملف `.github/workflows/pages.yml` يبني الموقع وينشره مع كل رفع إلى `main`.
1. **Settings** ← **Pages** ← **Source**: اختاري **GitHub Actions**.
2. **Settings** ← **Secrets and variables** ← **Actions** ← **New repository secret**، وأضيفي ثلاثة أسرار:
   `SUPABASE_URL` و `SUPABASE_PUBLISHABLE_KEY` و `WISHLIST_FAMILY_EMAIL`.
3. **Actions** ← **Deploy to GitHub Pages** ← **Run workflow**.
4. الرابط: `https://raghdalmehmadi.github.io/family-wishlist/`

إذا لم تُضف الأسرار بعد، يُنشر الموقع وتظهر فيه شاشة «بقيت خطوة الربط» إلى أن تضيفيها وتعيدي تشغيل النشر.
GitHub Pages المجاني يتطلب مستودعًا عامًا: الكود يصبح مرئيًا (بلا أي مفاتيح أو كلمات سر)، أما المنتجات والصور فتبقى محمية بكلمة سر العائلة في Supabase.

### Netlify
1. ارفعي المشروع إلى مستودع **خاص** على GitHub.
2. [Netlify](https://app.netlify.com): **Add new site** ← **Import an existing project** ← اختاري المستودع. الإعدادات تُقرأ من `netlify.toml`.
3. **Site configuration** ← **Environment variables**: أضيفي المتغيرات أعلاه.
4. **Deploys** ← **Trigger deploy**. سيظهر في السجل: `✓ js/config.js جاهز`.

> مع السحب والإفلات (Netlify Drop) لا يعمل أمر البناء؛ أنشئي `js/config.js` يدويًا قبل السحب.

### Vercel (بديل)
**Add New Project** ← المستودع ← **Framework Preset: Other** ← المتغيرات نفسها ← **Deploy**.

### بعد النشر
- أرسلي الرابط وكلمة السر للعائلة في رسالة خاصة.
- لإضافة الموقع إلى الشاشة الرئيسية: آيفون (Safari) زر المشاركة ← **إضافة إلى الشاشة الرئيسية**؛ أندرويد (Chrome) القائمة ⋮ ← **إضافة إلى الشاشة الرئيسية**.

## طريقة الاستخدام

- **الرئيسية**: هيدر شتوي فيه ماما وروان بمعطفَي سانتا، ثم ملخص المشتريات، ثم بطاقات الأقسام الست بألوانها (عدد المنتجات وعدد المشتراة في كل قسم).
- **داخل القسم**: أسماء الأفراد في قائمة جانبية (آيباد وكمبيوتر) أو شريط أفقي (جوال): الكل، ثم الأفراد الثمانية، ثم المنتجات المشتركة.
- **التصنيفات**: في الصيدلية والمكياج تظهر التصنيفات على شكل شبكة، وأولها «كل المنتجات». العطور والشنط والملابس والإكسسوارات تعرض المنتجات مباشرة، ويمكن إضافة تصنيفات لها من «إضافة تصنيف».
- **إضافة منتج**: اختاروا الشخص ثم التصنيف، ثم «إضافة منتج». النموذج ثلاثة حقول فقط: الاسم، والصورة (من الكاميرا أو الألبوم، اختيارية)، والوصف (اختياري). القسم والتصنيف والشخص تؤخذ من الصفحة المفتوحة، ويظهر ذلك أعلى النموذج.
  في «المنتجات المشتركة» يُضاف المنتج للعائلة كلها.
- **تم الشراء**: الدائرة الكبيرة في بداية كل منتج. الضغط عليها يُظهر علامة صح خضراء وعبارة «تم الشراء»، والضغط مرة أخرى يلغيها. وتظهر رسالة فيها «تراجع».
- **التصفية**: الكل / المتبقية / المشتراة.
- **التعديل والحذف والمشاركة**: زر ⋯ بجانب المنتج. «نقل إلى المنتجات المشتركة» يفتح قائمة بالأسماء لاختيار من يشترك فيه. شراء المنتج المشترك مرة واحدة يحدّث حالته عند الجميع، ويُحسب منتجًا واحدًا في الإحصائيات.
- **نصيحة لماما**: داخل القسم اختاري «الكل» ثم «كل المنتجات» ثم «المتبقية»؛ هكذا تظهر كل الطلبات الباقية في القسم في صفحة واحدة، وتحت كل منتج اسم صاحبه.
- **البحث**: أيقونة العدسة أعلى الصفحة، في جميع الأقسام.

## الأمان والبيانات

- لا قراءة ولا كتابة بدون كلمة سر العائلة (سياسات RLS على كل الجداول والصور).
- الصور في حاوية عامة للقراءة بأسماء عشوائية طويلة؛ لا يصل إليها إلا من يعرف رابطها الكامل.
- **تغيير كلمة السر**: احذفي المستخدم من **Authentication ← Users** وأنشئيه من جديد بالبريد نفسه وكلمة سر جديدة. المنتجات لا ترتبط بالمستخدم فلن يُحذف منها شيء.
- **بلا كلمة سر؟** شغّلي `supabase/open-access.sql` واجعلي `WISHLIST_AUTH_MODE=open`. حينها يستطيع أي شخص يملك الرابط تعديل القائمة.
- **الخطة المجانية**: Supabase يوقف المشاريع المجانية مؤقتًا إذا قلّ نشاطها خلال أسبوع، ويرسل بريد تنبيه قبل ذلك. البيانات لا تضيع، ويكفي **Resume project** من لوحة المشروع. افتحي الموقع قبل السفر بيوم للتأكد.

## ما الذي اختُبر

اختُبر الموقع آليًا في Chrome على جوال (390 بكسل) وآيباد (820 بكسل) منفصلين في الوقت نفسه: 91 فحصًا ناجحًا دون أي خطأ JavaScript، منها:
الدخول، ونصوص الهيدر، وألوان الأقسام، وغياب أسماء الأفراد عن الرئيسية، وخلوّ الواجهة من الإيموجي، وترتيب الأقسام والتصنيفات، والنموذج بحقوله الثلاثة، ورفع الصور وتصغيرها واستبدالها وإزالتها، وعلامة الشراء وإلغاؤها و«تراجع»، والتصفية، والمنتج المشترك واحتسابه مرة واحدة، والمزامنة اللحظية بين الجهازين (إضافة وشراء وتعديل وحذف)، وإضافة التصنيفات، والبحث، وفتح الصفحات الستين (كل قسم × كل خيار) وصفحات التصنيفات الـ48، وبقاء البيانات بعد التحديث، وعدم وجود تمرير أفقي.
واختُبر `schema.sql` على PostgreSQL 16: التثبيت الجديد مرتين، والترقية من الإصدار الأول مع نقل منتجات المكياج، ومنع غير المسجّلين.

**لم يُختبر** الاتصال بخوادم Supabase الحقيقية نفسها؛ اختُبر الموقع مقابل محاكٍ يطابق واجهة Supabase التي يستخدمها. أول تشغيل بعد الإعداد هو الاختبار الأخير: أضيفي منتجًا بصورة من جوالك، وافتحي الموقع من جهاز آخر.

## حلول سريعة

| ما يظهر | السبب المحتمل |
|---|---|
| «بقيت خطوة الربط» | `js/config.js` غير موجود أو ناقص، أو لم تُضبط متغيرات البيئة قبل النشر |
| «كلمة السر غير صحيحة» | البريد في الإعداد لا يطابق المستخدم في Supabase، أو المستخدم غير مؤكَّد |
| «تعذّر تحميل القائمة» | لم يُشغَّل `schema.sql`، أو المشروع متوقف مؤقتًا (Resume project) |
| لا يظهر قسم المكياج | شغّلي `schema.sql` الجديد مرة أخرى |
| «تعذّر رفع الصورة» | الصورة كبيرة جدًا أو بصيغة غير مدعومة؛ يمكن الحفظ دون صورة |
| التعديلات لا تظهر فورًا على جهاز آخر | راجعي الخطوة 6. والموقع يحدّث نفسه كل دقيقة وعند فتحه في كل الأحوال |
